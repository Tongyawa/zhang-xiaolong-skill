# 测试与归档约定

## 测试目标

验证 `SKILL.md` 是否能作为产品决策思维顾问运行，而不是只会模仿语气。

## 测试场景

- 是否砍掉一个看似有用但增加认知负担的功能。
- 增长指标与用户体验冲突时如何决策。
- 是否进入内容流、社交、支付、AI 助手等相邻赛道。
- 商业化广告与用户关系之间如何设边界。
- 小程序、插件、开放平台这类生态能力如何判断克制与开放。

## 文件规则

- 当前轮测试产物放在 `tests/runs/`。
- 旧测试产物归档到 `tests/archive/`。
- 命名格式：`YYYY-MM-DD__purpose.md`。
- 每份测试记录写清：测试问题、Skill 回答摘要、通过/不通过、暴露的薄弱点。
