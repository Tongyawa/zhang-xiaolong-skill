## 2. 关键对话模式

### 2.1 先把追问改写成底层问题

张小龙常把具体追问改写成更底层的定义问题：小程序不是“有没有入口”，而是“移动互联网时代服务如何被触达”；订阅号不是“要不要信息流”，而是“用户订阅内容如何提高阅读效率”；视频号不是“短视频产品”，而是“公开身份和结构化视频载体”。

思考方式（推断）：他不急于回答功能点，而是先重设问题边界。对产品决策而言，这会降低被行业热词牵着走的风险。

### 2.2 拒绝热词时，常用“我没有这样想过/这不是一回事”

典型热词包括“克制”“平台”“信息流”“流量红利”“强关系/弱关系”“中心化入口”。他不是简单否认，而是把词拆掉：克制被替换为合理性和对错；信息流被替换为用户掌控的订阅集合；入口被替换为任务栏/切换方式。

思考方式（推断）：拒绝语言框架，就是拒绝被外部 KPI 和商业预设绑定。

### 2.3 用类比把抽象平台问题落到身体经验

他解释“用完即走”时用汽车；解释小程序时用 PC 网站、二维码、餐馆排队、公交站；解释视频时用 Windows 文件和 Mac/iPhone 的文件感消失；解释朋友圈时用广场；解释直播时用“打开摄像头，别人提问，我回答”。

思考方式（推断）：类比不是修辞装饰，而是用一个更稳定的用户体验模型替代抽象概念。

### 2.4 允许不确定性存在，尤其面对社交产品

在“附近的人”“社交功能交给用户群体后的结果”“状态功能会怎样”“用户群体效应”上，他多次承认无法准确预测。这个不确定不是退缩，而是把风险纳入产品判断：先小范围、灰度、等待真实反馈。

思考方式（推断）：他把社交产品视为群体系统，不把设计者的意图等同于最终结果。

### 2.5 平台边界以“公平规则”而非“关系合作”表达

面对白名单、腾讯投资公司、合作资源交换、中心化导流、推送能力，他反复回到一条线：如果是普遍需求，做成系统规则；如果只是少数人靠关系拿特权，就破坏平台。

思考方式（推断）：平台不是靠谈合作来长大，而是靠可泛化、可预期、可被所有参与者共享的规则长大。

### 2.6 指标是验证，不是目标

2019 年他说新产品先看自然增长再推广；2021 年讲视频号时，先对关注/朋友赞/机器推荐的比例做推理，再跑数据验证。另一方面，他多次拒绝把用户时长当目标。

思考方式（推断）：先有产品假设，再用数据检验；不让数据指标反过来定义产品使命。

### 2.7 面对争议时，先承认外界误解可能来自微信表达不足

2018 年、2020 年、2021 年公开课中，他都解释为什么需要公开课：微信体量大后，一个动作会改变信息流向，外界也会有误解，需要在合适时间把背后想法讲清楚。

思考方式（推断）：他不是纯粹“产品自己说话”。当平台进入生态级规模后，他接受需要解释规则和理念。

## 3. 代表性回应：问法/上下文 -> 回应 -> 思考方式

### 3.1 用户体验与“用完即走”

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2016 微信公开课：行业追求用户黏性，为什么微信说好产品应“用完即走”？（S01，准一手） | 他把产品定义为工具，工具应最高效率完成任务，让用户离开去做别的事；用汽车作类比，车不是为了让人到达后继续坐在里面。 | 把体验目标从“留住用户”改成“完成任务”。产品好不好，不看用户困在里面多久，而看是否少占用用户生命。 |
| 2017 小程序发布前：外界嘲笑“微信黏性强才敢说用完即走”。（S02，准一手） | 他重新解释：用完即走的逻辑是工具使命；完成任务后离开，是效率的体现，不是用户永远不回来。 | 面对误解时补全定义，而不是换口号。核心是“效率”和“下次还愿意回来”的体验循环。 |
| 2018 公开课：用完即走是否和小游戏、小程序矛盾？（S03，准一手） | 他补出下半句：走了还会回来。小游戏也是小程序，点开就玩、无需安装卸载，也是即时完成任务。 | 他用场景而非品类判断：游戏也可以是工具式体验，关键是打开成本和退出成本。 |
| 2021 视频号：视频推荐会消耗很多时间，是否背离用完即走？（S06，准一手） | 他区分目标和结果：微信不把时长当 KPI；若用户停留，是因为内容值得看，而不是平台为了耗时设计。 | 给内容产品留下例外，但仍用“用户完成什么任务”约束。这里也埋下张力：视频号天然增加停留时间。 |

### 3.2 平台规则、边界与拒绝特权

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2016 公开课：为什么平台规则和接口这么严格、总在变化？（S01，准一手） | 他用前一晚“微信公开课数据传播”引发谣言和解绑银行卡的事件说明：微信量级下，小疏漏会被指数级放大；规则变化是因为平台自身也在演化。 | 平台规模改变风险函数。小产品能容忍的模糊，在十亿级产品上会变成系统性风险。 |
| 2016 公开课：内部/外部合作能否资源交换、拿特殊接口？（S01，准一手） | 他拒绝用资源交换替代用户价值；说平台更难的是挡掉多少事情。 | 决策先问“用户是否需要”，而不是“合作方是谁”。这是一种反业务关系驱动的边界。 |
| 2016 公开课：能否给少数人开好友数、红包金额白名单？（S01，准一手） | 他把白名单看作系统瑕疵：要么所有人没有特权，要么普遍需求变成规则。 | 平台公平性优先于个别大客户爽感。可泛化规则比一次性通融重要。 |
| 2019 公开课：腾讯投资的公司是否有平台倾斜？（S04，准一手） | 他明确说投资公司也应遵守平台规则，同时承认过去可能做得不够好，未来要更一视同仁。 | 保留矛盾：他宣称公平，但承认生态参与者已感到倾斜。Skill 后续不能把“去中心化”美化成已完全实现。 |
| 2021 视频号：平台会不会签约、买内容、强运营扶持创作者？（S06，准一手） | 他拒绝平台花钱买内容，认为创作者靠自身努力获得回报，才说明生态能自运转；规则和系统效率高于强运营。 | 平台角色是连接和载体，不是内容生产者或采购者。生态健康比短期内容繁荣更重要。 |

### 3.3 商业化与广告

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2016 公开课：微信如何商业化？（S01，准一手） | 他反对基于骚扰和纯流量变现的商业化；朋友圈广告要让用户不反感，优惠券要基于朋友背书和真实使用。 | 商业化必须嵌入用户本来要做的事；广告不是不能做，而是不能破坏用户和产品的朋友关系。 |
| 2019 公开课：启动页为什么不放广告？（S04，准一手） | 他用 IE/浏览器大流量页面不放广告作类比，又把微信比作老朋友，不希望用户每次见朋友先撕广告。 | 商业机会再大，也要看是否破坏关系界面。这里的“关系界面”不是 UI，而是用户对产品的长期信任。 |
| 2021 输入法：为什么微信要做输入法，是否会分析聊天记录做广告？（S06，准一手） | 他解释微信不会分析用户聊天记录，即使损失广告收入；输入法值得做的一点是安全性和未来输入形态。 | 隐私不是合规成本，而是产品边界。商业收入在某些体验/信任边界前让位。 |

### 3.4 小程序：入口、搜索、推送、生态

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2017 小程序：会不会有专门入口？（S02，准一手） | 没有中心入口；用户如果没运行过小程序，在微信里找不到它。前期更鼓励二维码触达。 | 入口不是流量红利，而是会重塑生态激励。没有入口，是逼服务回到真实场景。 |
| 2017 小程序：会不会做应用商店、分类、排行、推荐？（S02，准一手） | 不做小程序商店，也不做中心化分类排行推荐；查找和搜索另说。 | 他把“发现”拆成两类：用户主动找，与平台替用户分发。微信尽量避免后者。 |
| 2017 小程序：能不能推送消息？（S02，准一手） | 不能常规推送；只提供严格限制、由用户主动确认的服务通知。 | 推送是高骚扰能力，必须被约束在任务后续服务里。 |
| 2017 小程序：能不能分享到朋友圈？（S02，准一手） | 不能分享到朋友圈，但能分享到聊天和群；群分享不是传播入口，而是协作任务。 | 他拒绝最强扩散路径，把小程序放回“协作/服务”而不是“社交流量”。 |
| 2017 小程序：能否被搜索到？（S02，准一手） | 能搜到，但要限制搜索能力，避免小程序变成流量分发。 | 搜索是服务直达，不是排名红利。 |
| 2018 小程序下拉区域：外界认为这是中心化入口。（S03，准一手） | 他现场指出那更像任务栏/切换方式，而非入口。 | 通过产品结构区别“入口”和“找回”。同一个 UI，在生态激励上含义不同。 |
| 2018 小程序：是不是专门为电商准备？（S03，准一手） | 不是。小程序应是足够抽象的通用平台，不扶持某一领域。 | 拒绝用当前风口定义底层载体，保留跨行业创新空间。 |
| 2019 小程序：其他公司也做小程序，会不会威胁微信？（S04，准一手） | 他认为关键不在接口像不像，而在原动力；若只是流量生意，不看好。 | 同类形态不等于同类产品。底层动机会决定平台后续规则。 |

### 3.5 公众号、内容生态与信息流争议

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2016 公开课：公众平台是否只是媒体/流量平台？（S01，准一手） | 公众平台目标是让有价值的服务和创造触达用户，不是导流量；原创应得到保护和回报。 | 内容平台的核心不是流量，而是让价值可被发现、可获得回报。 |
| 2018 公开课：订阅号要不要做信息流？（S03，准一手） | 他对这个说法表示惊讶，订阅号是用户订阅集合；微信只改善阅读效率，不把它变成不受用户掌控的信息形式。 | 拒绝把“用户订阅”重构成“平台分发”。尊重用户选择权是边界。 |
| 2019 公开课：公众号改版后效果争议，流量红利消失怎么办？（S04，准一手） | 改版只是提高阅读效率；根本问题是内容是否有吸引力。平台应鼓励更多优质创作者，而非只改版面。 | 把“版式/入口问题”还原为“内容质量问题”。平台能力只能辅助，不能替代创作。 |
| 2020 公开课：公众号为何缺少短内容？（S05，准一手） | 他承认公众号最初不应只成为文章载体，短内容缺失是失误之一；每个人都能表达的载体不足。 | 保留自我修正：早期抽象不足，导致内容形态被长文锁住。 |
| 2020 公开课：信息推荐与“分发”的差别？（S05，准一手） | 他更少使用“分发”，觉得“推荐”更尊重；平台推什么，会决定用户处在怎样的信息世界。 | 语言选择体现价值边界：平台不是命令信息流向，而是承担推荐责任。 |

### 3.6 视频号、直播与推荐

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2021 视频号：它到底是什么？（S06，准一手） | 他把视频号定义为公开领域的内容平台，但重点不只在视频，而在“号”：每个人拥有一个公开发声身份。 | 先看身份系统，再看内容形态。视频只是表层，公开身份才是结构变化。 |
| 2021 视频号：为什么不直接沿用微信号身份？（S06，准一手） | 微信 ID 基于私密社交和通信，不适合公开领域；视频号需要另一套公开身份。 | 区分私域身份与公域身份。平台边界来自身份边界，而不只是权限设置。 |
| 2021 视频号：为什么后来没有强制每人创建新 ID？（S06，准一手） | 强制新 ID 会让社交推荐路径走不通，因此放弃。 | 产品选择不是单点最优，而是保留关键增长/传播机制。 |
| 2021 推荐：机器推荐还是社交推荐？（S06，准一手） | 早期内容稀缺时，机器推荐走不下去，朋友点赞反而更好；社交推荐帮助视频号过生死线，内容丰富后机器推荐才更有效。 | 推荐机制要匹配内容供给阶段。算法不是越早越好，冷启动阶段关系链可能更有解释力。 |
| 2021 推荐比例：关注/朋友赞/机器推荐应如何分配？（S06，准一手） | 他先做 1:2:10 的推理，再让同事跑活跃用户数据验证方向。 | 先建立行为模型，再用数据验证；数据不是替代判断，而是校验推理。 |
| 2021 视频内容：视频是文件、网页还是视频本身？（S06，准一手） | 他认为未来视频应是云端结构化数据，不是本地文件；视频号是视频内容载体，类似公众号之于文章。 | 产品定义从“文件格式”升维到“结构化关系”：创作者、评论、传播、沉淀。 |
| 2021 长短视频：视频号如何兼容长视频？（S06，准一手） | 他最终取消长短视频的专门区分，把长视频前一分钟视为封面。 | 拒绝人为分类，寻找统一结构。分类不是越细越好，统一规则能降低复杂度。 |
| 2021 全屏化：为什么视频号不是一开始就全屏？（S06，准一手） | 他用“命中率”解释：命中率低时一屏多条让用户选择，命中率高才适合全屏；朋友圈若全屏会死。 | UI 形态由内容命中率决定，不由行业潮流决定。 |
| 2021 直播：为什么直播可能比短视频更适合普通人？（S06，准一手） | 他用自己内部直播经验说，短视频要准备和精致，直播只要打开镜头、面对提问回答即可。 | 即兴表达比精致创作门槛低；他把直播看成更轻的个人表达形态，而不只是秀场/带货。 |

### 3.7 社交、朋友圈与用户压力

| 问法/上下文 | 张小龙回应 | 反映的思考方式 |
|---|---|---|
| 2013 采访：强关系/弱关系是否解释微信？（S09，准一手） | 他不太用这套概念；用户通信录里什么人都有，关系会转化，微信不做分组也不按概念限定产品。 | 拒绝学术/行业概念先行，回到真实使用混杂性。 |
| 2013 采访：朋友圈为何默认鼓励发照片而不是纯文字？（S09，准一手） | 文字门槛高，照片每个人都会发；产品目标是老人、小孩、普通人都能用。 | 为“所有人”设计，而不是为表达能力强的小众设计。降低普通人心理门槛比满足高手表达更重要。 |
| 2019 公开课：社交的起源和朋友圈压力是什么？（S04，准一手） | 他把朋友圈比作广场：高效完成熟人社交，但点赞评论像在广场发声，会带来压力。 | 用场景模型解释社交压力：可见范围越大，表达成本越高。 |

| 2021 状态：为什么要做状态？结果会怎样？（S06，准一手） | 他承认不知道结果；社交产品交给群体后难预测，但个人状态表达需求未被满足，因此值得试。 | 在不确定中行动：只要未满足需求真实存在，就可小步试，而不是等确定答案。 |

### 3.8 方法论、团队与产品经理能力

|---|---|---|
| 2012 采访：微信是不是 QQ 的手机版？（S10，准一手） | 他不纠结外界怎么定义；用户会选择，内部竞争正常。 | 不把防御性解释当重点。产品定位最终由用户行为验证。 |

## 4. 拒绝问题与转移框架的方式

### 4.1 “我不回答这个定义，你自己在产品里看”

代表：2019 启动页含义、2013 “为什么选这首歌”、微信/公众平台是什么。

模式：遇到象征性、解释空间大的问题，他不提供标准答案，甚至把问题抛回给用户。不是逃避，而是让产品保留多义性，避免被一个解释限制。

对决策的启发：如果一个产品符号的价值来自用户投射，不要过早官方解释；解释会缩小空间。

### 4.2 “这不是我脑子里的词”

代表：克制、信息流、强弱关系、风口、平台。

模式：先拆词，再给自己的底层词汇：合理性、订阅集合、工具、载体、用户掌控、原动力。

对决策的启发：遇到争论，先检查争论词是否已经偷渡了商业目标。

### 4.3 “如果是普遍需求，就做成规则；如果是少数特权，就不做”

代表：白名单、红包金额、好友数、腾讯投资公司、中心入口。

模式：拒绝个案特权，但不否认需求本身；把需求放回系统规则层。

对决策的启发：平台产品面对大客户、内部业务、明星创作者时，最危险的不是满足需求，而是以例外方式满足需求。

### 4.4 “我不知道结果会怎样，但需求存在”

代表：附近的人、状态、视频动态、社交功能群体反应。

模式：承认不确定，同时用“需求是否未满足”决定是否尝试。

对决策的启发：不确定不是不做；但做法应是灰度、低耦合、可回收。

## 6. 保留的矛盾与含糊

### 6.1 “微信是工具”与“微信必须平台化”

他在公开演讲里反复说微信是工具，用户不关心平台/生态；但 2013 腾讯月刊专访中也说，如果微信不做大、不平台化，就会死掉。可理解为：用户触碰层应像工具，系统战略层必须具备平台能力。但这不是他完全展开的统一理论。

后续提炼注意：不能把“工具”理解为小而单一；他的“工具”可以包含巨大平台，只要用户感知仍简单。

### 6.2 “去中心化”与微信本身的中心化控制

他坚持不做中心化导流、不推荐公众号/小程序，但微信掌握搜索、规则、入口、推荐、封禁、身份体系。2019 年他还承认外界认为腾讯投资公司有倾斜，可能是微信做得不够好。

后续提炼注意：去中心化是价值取向，不是客观状态。平台越大，越需要警惕自己成为中心。

### 6.3 “不做信息流”与视频号推荐流

2018 年他拒绝订阅号做信息流，强调用户订阅和掌控；2021 年视频号明确采用关注、朋友赞、机器推荐等信息流结构。可区分为：订阅号是用户主动订阅内容，不应被改造成平台分发；视频号是公开内容平台，本身需要流式消费。但这一区分仍有张力。

后续提炼注意：他反对的不是所有 feed，而是把用户本来掌控的订阅关系改造成不可控分发。

### 6.4 “用完即走”与视频/直播增加停留时间

他解释时长只是结果，不是目标。但视频号、直播、推荐天然提高时长。此处只能保留为产品张力：如果内容确实值得看，用户停留被视为价值结果；若为 KPI 设计停留，则被视为违背原则。

后续提炼注意：判断关键不是“用户是否花时间”，而是“这段时间是不是用户愿意付出的内容消费/表达/任务时间”。

### 6.5 “不从文化出发”与高度依赖人性/社交心理

2013 采访中他反对把国际化失败归因于文化，主张从需求分析；但 2012/2019 演讲又大量讨论人性、社交、群体效应、用户土壤。两者并不完全矛盾，但说明他更愿意分析可操作的需求和心理机制，而不是宏观文化标签。

后续提炼注意：避免把他写成文化决定论者；他看人性，但不爱用宏大文化解释偷懒。

### 6.6 “用户价值”与用户短期抱怨

7.0 改版、聊天记录不云端同步、朋友圈三天可见、推送限制等，都会带来用户抱怨或不便。他不是按用户投票，而是用专业判断决定什么长期对用户好。

后续提炼注意：他的“尊重用户”不是满足用户所有即时要求，而是保护长期体验和边界。

## 7. 产品决策启发（供后续提炼，不是最终 Skill）

1. 先问用户要完成什么，再讨论功能形态。功能名、行业词、竞品形态都不能替代任务本身。
2. 面对增长诱惑，先算骚扰成本。能触达用户不代表应该触达用户。
3. 平台能力要么普遍规则化，要么不要做；不要靠白名单、关系户、特权接口解决需求。
4. 对“入口”的判断不能只看 UI，还要看生态激励：入口会制造争夺，任务栏只是找回。
5. 不要把“提高用户时长”当目标。时长只能是用户获得价值后的副产品。
6. 数据用于验证推理，不用于替代产品判断。先说清楚为什么应该这样，再看数据是否支持。
7. 内容平台早期不要过度依赖机器推荐；内容不丰富时，关系链和人工选择可能更能建立生死线。
8. 推荐、全屏、瀑布流、摘要卡片等 UI 选择，要看内容命中率和用户选择成本，不看行业流行。
9. 内容生态里，平台应做载体、规则和回报机制，少做内容采购和强运营。
10. 对普通人表达产品，降低心理门槛比提供高阶表达能力更重要。
11. 保留产品的抽象性：不要过早把平台定义成“电商”“媒体”“CRM”“短视频”，否则会限制长出来的东西。
12. 社交产品交给群体后会产生不可预测结果；因此要小团队、快迭代、灰度、可回收。
13. 对用户隐私和长期信任的边界，不应被短期广告收入穿透。
14. 当外界追问“为什么不做 X”时，先判断 X 是用户真实任务，还是商业方/运营方/创作者想要的触达权。
15. 对产品经理方法论保持怀疑：可沉淀启发式，但不要承诺“照做 A 必得 B”。
